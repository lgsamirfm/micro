۱. سلسله‌مراتب زبان‌ها احتمال خیلی بالا

برنامه کامپیوتری در نهایت باید به زبانی تبدیل شود که سخت‌افزار بتواند آن را اجرا کند. ترتیب کلی شکل اسلاید:

زبان سطح بالا
مانند C، C++، C#، Java، Basic، Fortran و Cobol.
زبان اسمبلی
زبان سطح پایین‌تر و وابسته به پردازنده؛ با نمادهای قابل‌خواندن‌تر از زبان ماشین.
زبان ماشین
دستورهای قابل‌فهم برای سخت‌افزار که به شکل صفر و یک نمایش داده می‌شوند.
  • زبان‌های سطح بالا عموماً غیر وابسته به ماشین هستند.
  • زبان‌های سطح پایین، از جمله اسمبلی و ماشین، وابسته به ماشین هستند.
  • جزئیات اجرای برنامه در ماشین از نویسنده برنامه سطح بالا پنهان است.
  • هر دستور زبان سطح بالا ممکن است به چندین دستور زبان ماشین تبدیل شود.

زبان اسمبلی چیست؟

  • از نام‌های سمبولیک برای مشخص‌کردن عملگرها، ثبات‌ها و خانه‌های حافظه استفاده می‌کند.
  • از زبان ماشین سطح بالاتری دارد و خوانایی آن بیشتر است.
  • رابطه آن با دستورهای زبان ماشین یک‌به‌یک است (طبق اسلاید).
  • هر خانواده پردازنده زبان اسمبلی مخصوص خود را دارد.
  • به سخت‌افزار وابسته است؛ هر پردازنده دستورهای مربوط به خود را دارد.

زبان ماشین

  • زبان قابل فهم برای کامپیوتر و وابسته به سخت‌افزار است.
  • در نمایش انسانی از صفر و یک استفاده می‌کند؛ در اسلاید از آن به‌عنوان «زبان ولتاژ» نیز یاد شده است.
حفظی: High-level = خواناتر و مستقل‌تر از ماشین؛ Assembly = نمادین ولی وابسته به پردازنده؛ Machine = صفر و یک و قابل اجرای مستقیم توسط سخت‌افزار.

۲. مثال تبدیل برنامه از C به اسمبلی و ماشین

در مثال اسلاید، هدف جمع دو عدد ۴ و ۵ و قراردادن نتیجه در خروجی P0 است.

کد سطح بالا (C)

#include <stdio.h>
int x = 4, y = 5;
int z;
int main()
{
    z = x + y;
    printf("%d\n", z);
}

معادل اسمبلی نشان‌داده‌شده در اسلاید

MOV 22H, 4
MOV 23H, 5
MOV A, 22H
ADD A, 23H
MOV 24H, A
MOV P0, 24H
  • عدد ۴ در آدرس 22H و عدد ۵ در آدرس 23H قرار می‌گیرد.
  • مقدار آدرس 22H به ثبات A منتقل می‌شود.
  • مقدار آدرس 23H به A اضافه می‌شود.
  • نتیجه در آدرس 24H ذخیره و سپس به P0 منتقل می‌شود.
نکته: اسلایدهای ۷ تا ۹ همین مثال را مرحله‌به‌مرحله از کد C به اسمبلی و سپس نمایش باینری نشان می‌دهند. ممکن است سؤال مفهومیِ «ترجمه در سطوح مختلف» از این شکل طرح شود.

۳. مزایا و محدودیت‌های زبان سطح بالا احتمال بالا

مزایای زبان سطح بالا

  • برنامه‌نویسی سریع‌تر است.
  • به تعداد دستورهای کمتری نیاز دارد.
  • عیب‌یابی برنامه ساده‌تر است.
  • برنامه‌ها قابل‌حمل (Portable) هستند.
  • وابستگی کمتری به ماشین دارند و با تغییر کم یا بدون تغییر می‌توان آن‌ها را به ماشین‌های دیگر منتقل کرد.
  • کامپایلر زبان سطح بالا را به زبان اسمبلی مربوطه ترجمه می‌کند (طبق بیان اسلاید).

محدودیت اسمبلی

  • برنامه‌های اسمبلی Portable نیستند و فقط برای همان پردازنده نوشته شده‌اند.
سؤال مقایسه‌ای: چرا زبان سطح بالا قابل‌حمل‌تر است؟ چون کمتر به ماشین وابسته است؛ اما اسمبلی به دستورهای اختصاصی پردازنده وابسته است.

۴. فواید و دلایل استفاده از زبان اسمبلی احتمال خیلی بالا

فواید اسمبلی (چه چیزهایی را آشکار می‌کند؟)

  1. نشان می‌دهد برنامه چگونه با پردازنده، سیستم‌عامل و BIOS ارتباط برقرار می‌کند.
  2. نشان می‌دهد داده چگونه روی حافظه یا دستگاه‌های جانبی ذخیره می‌شود.
  3. نشان می‌دهد پردازنده چگونه دستورها را اجرا می‌کند و دستورها چگونه به داده‌ها دسترسی پیدا می‌کنند.
  4. نشان می‌دهد برنامه چگونه به دستگاه‌های خارجی دسترسی پیدا می‌کند.

دلایل استفاده از اسمبلی

  • برنامه اسمبلی نسبت به برنامه مشابه سطح بالا حافظه کمتری نیاز دارد و سرعت اجرای بالاتری دارد.
  • به برنامه‌نویس امکان استفاده از تکنیک‌هایی را می‌دهد که در زبان سطح بالا بسیار سخت یا گاهی غیرممکن‌اند.
  • با اینکه اغلب برنامه‌ها با زبان سطح بالا نوشته می‌شوند، بخش‌های بحرانی از نظر زمان اجرا ممکن است با اسمبلی بازنویسی شوند.
  • برنامه‌های سیستمی که هنگام اجرای سایر برنامه‌ها در حافظه می‌مانند و درایورهای سخت‌افزار برای کنترل ورودی/خروجی، تقریباً همیشه با اسمبلی نوشته می‌شوند (طبق اسلاید).
نکته امتحانی: «حافظه کمتر + سرعت اجرای بیشتر + کنترل سطح پایین‌تر» سه دلیل کلیدی استفاده از اسمبلی‌اند.

۵. ابزارهای برنامه‌نویسی (Language Programming Tools)

شش ابزار اصلی که در اسلاید معرفی شده‌اند:

ابزاروظیفه اصلی
Compilerترجمه دستورهای زبان سطح بالا به زبان اسمبلی (طبق تعریف اسلاید).
Assemblerترجمه کد اسمبلی به زبان ماشین و تولید Object File.
Linkerادغام فایل‌های Object و کتابخانه‌های موردنیاز و ساخت فایل اجرایی.
Loaderانتقال فایل اجرایی از حافظه جانبی به RAM و آغاز اجرای آن.
DebuggerTrace کردن برنامه و مشاهده کد، حافظه و مقادیر ثبات‌ها.
Editorساخت Source Code؛ بعضی ویرایشگرها قابلیت نمایش Syntax دارند.
ترتیب کلی مسیر تولید و اجرای برنامه:
High-level source → Compiler → Assembly source → Assembler → Object file → Linker → Executable file → Loader → Memory

در شکل سلسله‌مراتب ترجمه، کتابخانه‌های ماشین نیز به Linker داده می‌شوند. Debugger و Editor ابزارهای کمکی در فرایند توسعه‌اند و در مسیر خطی تولید فایل اجرایی قرار نگرفته‌اند.

۶. Compiler در برابر Assembler احتمال خیلی بالا

CompilerAssembler
ورودی: زبان سطح بالاورودی: زبان اسمبلی
خروجیِ مطرح‌شده در اسلاید: زبان اسمبلیخروجی: Object File شامل کد ماشین و اطلاعات مرتبط
هر دستور سطح بالا ممکن است به چند دستور سطح پایین تبدیل شود.دستورهای اسمبلی را به دستورهای زبان ماشین ترجمه می‌کند؛ رابطه یک‌به‌یک در اسلاید مطرح شده است.
تعریف Compiler: برنامه‌ای است که دستورات نوشته‌شده با زبان سطح بالا را به زبان اسمبلی ترجمه می‌کند.
تعریف Assembler: برنامه‌ای است که کدهای نوشته‌شده به زبان اسمبلی را به فایل Object تبدیل می‌کند؛ دستورهای اسمبلی را به زبان ماشین ترجمه می‌کند.

۷. اسمبلر و دو گذر آن (Two-pass Assembler) احتمال خیلی بالا

  • اسمبلر اعداد دهدهی و هگزادسیمال را به اعداد باینری تبدیل می‌کند.
  • فایل Object ترکیبی از دستورها، داده‌ها و اطلاعات لازم برای قرار دادن داده‌ها در حافظه است.

گذر اول (Pass 1)

  1. برنامه خط‌به‌خط خوانده می‌شود.
  2. برچسب‌ها (Labels) شناسایی می‌شوند.
  3. برچسب‌ها در جدول نمادها (Symbol Table) ذخیره می‌شوند.

گذر دوم (Pass 2)

  1. اطلاعات موجود در Symbol Table استفاده می‌شود.
  2. برای هر خط برنامه، کد ماشین تولید می‌شود.
حفظی دقیق: Pass 1 = خواندن برنامه و ساخت Symbol Table؛ Pass 2 = استفاده از Symbol Table و تولید کد ماشین.

۸. اجزای فایل Object احتمال خیلی بالا

بخشمحتوا / وظیفه
Headerاندازه و مکان شروع سایر قسمت‌ها.
Text Segmentدستورها به زبان ماشین.
Data Segmentداده‌ها به صورت باینری.
Relocation Informationدستورها و داده‌هایی که به آدرس مطلق نیاز دارند.
Symbol Tableآدرس‌ها، برچسب‌های خارجی و فهرست ارجاع‌های حل‌نشده.
Debugging Informationاطلاعات مربوط به دیباگ.
ترفند حفظی: Header = نقشه و اندازه؛ Text = کد؛ Data = داده؛ Relocation = آدرس‌دهی؛ Symbol = نمادها و ارجاع‌ها؛ Debugging = اطلاعات اشکال‌زدایی.

۹. Linker و Link Libraries احتمال بالا

  • برای تولید برنامه قابل اجرا، در کنار اسمبلر به Linker نیاز است.
  • یک برنامه می‌تواند از چند برنامه یا چند فایل کد تشکیل شود.
  • اسمبلر هر فایل کد را جداگانه به فایل Object تبدیل می‌کند.
  • Linker فایل‌های Object را با سایر فایل‌های Object و Link Libraryها ادغام می‌کند.
  • خروجی Linker یک فایل قابل اجرا (Executable File) است.
نکته شکل صفحات ۲۳ و ۲۴: چند Source File جداگانه → هرکدام توسط Assembler به Object File تبدیل می‌شوند → Objectها به همراه Link Libraries وارد Linker می‌شوند → یک Executable File ساخته می‌شود.

Relocation و Jump/Link در شکل

در شکل صفحه ۲۳، فایل Object شامل دستورهای فراخوانی و رکوردهای Relocation است. Linker آدرس‌های لازم را با درنظرگرفتن فایل‌های دیگر و کتابخانه حل می‌کند؛ در خروجی اجرایی، فراخوانی‌های نامشخص با مقصدهای مشخص مانند printf و sub جایگزین شده‌اند.

۱۰. Loader، Debugger و Editor

Loader

قسمتی از سیستم‌عامل است که فایل قابل اجرا را از حافظه جانبی به حافظه RAM منتقل می‌کند و اجرای آن را آغاز می‌کند.

Debugger

  • برای Trace کردن برنامه استفاده می‌شود.
  • می‌توان کد برنامه، حافظه و مقادیر ثبات‌ها (Registers) را مشاهده کرد.

Editor

  • برای ساخت Source Code استفاده می‌شود.
  • بعضی Editorها ویژگی نمایش Syntax دارند.
سه‌گانه‌ای که قاطی نشود: Editor کد را می‌نویسد؛ Debugger اجرای برنامه و وضعیت حافظه/ثبات‌ها را بررسی می‌کند؛ Loader فایل اجرایی را در RAM بارگذاری و اجرا را شروع می‌کند.

۱۱. پرسش‌های احتمالی امتحان با جواب

  1. زبان سطح بالا چه ویژگی‌هایی دارد؟
    خوانایی و سرعت برنامه‌نویسی بیشتر، دستورهای کمتر، عیب‌یابی ساده‌تر و قابلیت انتقال بهتر بین ماشین‌ها.
  2. چرا اسمبلی وابسته به ماشین است؟
    چون هر خانواده پردازنده دستورهای اسمبلی مخصوص خود را دارد.
  3. زبان اسمبلی از چه نمادهایی استفاده می‌کند؟
    از نام‌های سمبولیک برای عملگرها، ثبات‌ها و خانه‌های حافظه.
  4. چرا از اسمبلی استفاده می‌کنیم؟
    مصرف حافظه کمتر، سرعت اجرای بالاتر و امکان کنترل/تکنیک‌های سطح پایین.
  5. چه بخش‌هایی از برنامه ممکن است با اسمبلی بازنویسی شوند؟
    بخش‌های بحرانی از نظر زمان اجرا.
  6. چه نوع برنامه‌هایی تقریباً همیشه با اسمبلی نوشته می‌شوند؟
    برنامه‌های سیستمی و درایورهای سخت‌افزار (طبق اسلاید).
  7. Compiler چه کاری انجام می‌دهد؟
    دستورات زبان سطح بالا را به زبان اسمبلی ترجمه می‌کند.
  8. Assembler چه کاری انجام می‌دهد؟
    کد اسمبلی را به زبان ماشین ترجمه و فایل Object تولید می‌کند.
  9. دو گذر اسمبلر را توضیح دهید.
    گذر اول: خواندن خط‌به‌خط و ذخیره Labelها در Symbol Table؛ گذر دوم: استفاده از جدول و تولید کد ماشین.
  10. شش بخش فایل Object کدام‌اند؟
    Header، Text Segment، Data Segment، Relocation Information، Symbol Table و Debugging Information.
  11. وظیفه Linker چیست؟
    ادغام فایل‌های Object با سایر Objectها و کتابخانه‌ها و تولید فایل اجرایی.
  12. وظیفه Loader چیست؟
    انتقال فایل اجرایی از حافظه جانبی به RAM و آغاز اجرای آن.
  13. Debugger چه اطلاعاتی را نمایش می‌دهد؟
    کد، حافظه و مقادیر ثبات‌ها را برای Trace برنامه.
  14. Editor چیست؟
    ابزاری برای ساخت Source Code؛ برخی از آن‌ها Syntax را نیز نمایش می‌دهند.
  15. تفاوت فایل Object و Executable چیست؟
    Object خروجی اسمبلر است و ممکن است هنوز به فایل‌ها و کتابخانه‌های دیگر نیاز داشته باشد؛ Linker آن‌ها را ادغام می‌کند و فایل اجرایی می‌سازد.
